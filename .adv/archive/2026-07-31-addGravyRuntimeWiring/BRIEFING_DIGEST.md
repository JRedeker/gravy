- **[archive_only_evidence]** architecture_assessment: PREMISE IS LIKELY MISTAKEN. The documented 443/8443/10000 restriction is Funnel-only (public relay, enforced by relay servers that only listen on those ports). `tailscale serve` (tailnet-only, which Gravy uses) accepts ARBITRARY HTTPS ports: proven by (a) Serve CLI docs showing no port restriction, (b) tailscale source ServeConfig where TCP/Web are keyed by arbitrary uint16 port and AllowFunnel is a separate gate, (c) issue #11009 showing `serve --https=9123` producing a live config, (d) a production multi-port serve config (443+3001+3002) on one node. Gravy reviews are 'Tailnet-reachable' (AGENTS.md), i.e. reviewers are tailnet members - Serve is the correct tool, not Funnel. Therefore the current distinct-port-per-review design (17000+ each mapped via `tailscale serve --https=<port> localhost:<port>`) is structurally sound and supports >=10 concurrent isolated reviews: one cert per machine covers all ports, each mapping is a state entry in tailscaled (no per-review process), and the code never runs `tailscale serve reset`. The likely REAL root causes of the observed exposure_failure are: (1) HTTPS certificates not enabled/provisioned in the tailnet (Serve docs require this; the code's https_available() only checks MagicDNSEnabled+DNSName, NOT cert readiness - a real preflight gap), (2) cert-provision latency on first expose exceeding the 10s timeout, or (3) the orchestrator misdiagnosed by reading the Funnel limitation and projecting it onto Serve. I cannot run the tailscale binary from this agent (no shell tool), so I cannot empirically confirm the local environment; the orchestrator should disambiguate with a one-command serve test. Path-routing/shared-local-proxy is a WORSE option: Gradio does not tolerate non-root paths well (asset/WebSocket URLs assume root), it violates the approved architecture ('intentionally avoids ... shared-origin reverse proxy'), and it is only NECESSARY under Funnel's 3-port cap - which does not apply to tailnet-reachable Serve. DISTINCT-PORT Serve is the by-the-book pattern and is what the codebase already does.
